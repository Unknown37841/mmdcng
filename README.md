# Sub Merger + Health Checker (VLESS)

این پروژه چند تا ساب لینک VLESS رو می‌گیره، سلامت هر کانفیگ رو تست می‌کنه، و یک
ساب خروجی می‌سازه که فقط شامل سریع‌ترین و سالم‌ترین کانفیگ‌هاست.

## منطق کار
1. هر ساب ورودی از `subs.txt` خونده و دانلود میشه.
2. محتوای هر ساب (base64) دیکد میشه و کانفیگ‌های `vless://` استخراج میشن.
3. برای هر کانفیگ، یک اتصال TCP خام به `host:port` تست میشه و تاخیر (ping) اندازه‌گیری میشه.
4. اگر **همه‌ی** کانفیگ‌های یک ساب قطع بودن → کل اون ساب از خروجی حذف میشه.
5. اگر بخشی از کانفیگ‌ها زنده بودن → فقط `TOP_N` (پیش‌فرض ۳) تا سریع‌ترین از همون ساب نگه داشته میشه.
6. نتیجه‌ی نهایی (ترکیب همه‌ی ساب‌های زنده) به صورت base64 در `output_sub.txt` نوشته میشه.
7. یک گزارش خوانا هم در `report.txt` ذخیره میشه (چه سابی حذف شد، چند تا کانفیگ از هرکدوم زنده بود).

> نکته مهم: تست فعلی فقط "باز بودن پورت روی سرور" رو چک می‌کنه (TCP connect)،
> نه هندشیک کامل VLESS. این کار عمداً اینطوریه تا بدون نصب هیچ باینری اضافه‌ای
> (مثل xray-core) روی ران‌رهای رایگان گیت‌هاب اکشن اجرا بشه. اگر بعداً خواستی
> تست واقعی‌تر (هندشیک کامل TLS/Reality) داشته باشی، باید xray-core رو در
> ورک‌فلو نصب کنی و برای هر کانفیگ یک پراکسی موقت بالا بیاری و یک درخواست HTTP
> واقعی از توش رد کنی؛ کندتره ولی دقیق‌تره. بگو تا همون نسخه رو هم برات بسازم.

## راه‌اندازی (قدم به قدم)

1. یک ریپوی عمومی (public) جدید در گیت‌هاب بساز.
2. سه فایل زیر رو داخلش قرار بده (ساختار پوشه‌ها رو حفظ کن):
   - `check_and_build.py`
   - `subs.txt`
   - `.github/workflows/update.yml`
3. داخل `subs.txt` لینک ساب‌های خودت رو بذار (هر خط یک لینک، خطوط با # کامنت هستن).
4. برو تب **Settings > Actions > General** ریپو، و زیر «Workflow permissions»
   گزینه‌ی **Read and write permissions** رو فعال کن (تا ورک‌فلو بتونه commit/push کنه).
5. برو تب **Actions**، ورک‌فلوی «Update Subscription» رو پیدا کن و یک بار
   دستی (`Run workflow`) اجراش کن تا `output_sub.txt` اولیه ساخته بشه.
6. از اون به بعد هر ۳ ساعت یک‌بار خودکار اجرا میشه (میتونی زمان‌بندی `cron` رو
   در `update.yml` عوض کنی، مثلاً `0 */1 * * *` برای هر ساعت).

## آدرس ساب خروجی

بعد از اولین اجرا، لینک زیر همون ساب نهایی توئه (USERNAME و REPO رو عوض کن):

```
https://raw.githubusercontent.com/USERNAME/REPO/main/output_sub.txt
```

اگر `raw.githubusercontent.com` براتون فیلتر/کند بود، از آینه‌ی jsDelivr
استفاده کن که معمولاً سریع‌تر و در دسترس‌تره:

```
https://cdn.jsdelivr.net/gh/USERNAME/REPO@main/output_sub.txt
```
(توجه: jsDelivr کش داره، ممکنه چند دقیقه طول بکشه تا آپدیت جدید رو نشون بده.)

## تنظیمات قابل تغییر (بالای فایل check_and_build.py)

- `TOP_N` — چند تا کانفیگ سریع از هر ساب نگه داشته بشه (پیش‌فرض ۳)
- `TIMEOUT` — حداکثر زمان انتظار برای هر تلاش اتصال (ثانیه)
- `RETRIES` — چند بار هر کانفیگ تست بشه (بهترین نتیجه نگه داشته میشه)

## محدودیت‌های نسخه رایگان گیت‌هاب اکشن

- برای ریپوی **public** دقیقه‌های اجرای رایگان عملاً نامحدوده (فقط سقف‌های نرم
  استفاده‌ی منصفانه‌ی گیت‌هاب رو رعایت کن، مثلاً هر اجرا رو خیلی کوتاه نگه دار).
- کران گیت‌هاب اکشن گارانتی دقیقه‌به‌دقیقه نیست؛ با بار ۳۰ دقیقه‌ای ممکنه گاهی
  چند دقیقه دیرتر اجرا بشه، طبیعیه.
- ⚠️ گیت‌هاب به صورت خودکار **scheduled workflow ها رو بعد از ۶۰ روز عدم فعالیت
  ریپو (بدون هیچ commit) غیرفعال می‌کنه**. چون این پروژه با هر اجرا خودش commit
  می‌زنه (وقتی خروجی تغییر کنه) معمولاً مشکلی پیش نمیاد، ولی اگه یک مدت طولانی
  همه‌ی سرورها زنده بودن و خروجی عوض نشد، ممکنه لازم بشه یک بار دستی از تب
  Actions اجراش کنی.
- تعداد ساب‌های داخل `subs.txt` هیچ محدودیتی نداره؛ هر خط یک ساب اضافه‌ست، فقط
  هرچی تعداد بیشتر باشه، هر اجرا کمی بیشتر طول می‌کشه (چون تست‌ها به‌ترتیب انجام می‌شن).

## درباره‌ی روش تست (چرا فقط TCP کافی نبود)

خیلی از کانفیگ‌های VLESS پشت CDN مثل کلادفلر هستن (مثل نمونه‌ای که با
`type=ws&security=tls` و آدرس IP کلادفلر مشخصه). در این حالت آدرس سرور یک IP
عمومی و اشتراکی کلادفلره که تقریباً همیشه در دسترسه، حتی اگه ورکر یا توکن پشتش
از کار افتاده باشه. برای همین این اسکریپت به جای یک TCP connect ساده، یک
**درخواست واقعی WebSocket Upgrade** (با TLS + SNI + Host + Path درست) می‌فرسته
و فقط جوابِ `HTTP 101 Switching Protocols` رو «زنده» حساب می‌کنه. برای انواع
دیگه‌ی transport (تی‌سی‌پی ساده، gRPC و...) فعلاً همون TCP(+TLS) connect به
عنوان تست پایه استفاده می‌شه.
